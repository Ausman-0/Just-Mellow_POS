# JUST MELLOW POS — Round 1

ระบบขายและรายงานสำหรับร้านขนมและเครื่องดื่มขนาดเล็ก พัฒนาเป็น Progressive Web App (PWA) แบบ local-first โดยเวอร์ชันนี้เน้นการขาย บันทึกบิล ประวัติ รายงาน CSV และการสำรองข้อมูลด้วยตนเอง/ผ่าน Supabase

## ฟังก์ชันที่มี

- หน้าขายบนมือถือ ค้นหาเมนู กรองหมวด เพิ่ม/ลดจำนวน และคำนวณยอดรวม
- บันทึกบิลพร้อมหมายเลขบิลที่ไม่ซ้ำกัน วิธีชำระเงิน และรายละเอียดเงินสด/เงินทอน
- ประวัติ ค้นหาบิล ดูรายละเอียด และยกเลิกบิลพร้อมเหตุผล โดยไม่ลบประวัติ
- รายงานยอดขาย ต้นทุน/กำไรขั้นต้น วิธีชำระเงิน และสินค้าขายดี/ยอดขายต่ำ
- ส่งออก CSV แยก 5 ประเภท โดยมี BOM UTF-8 สำหรับภาษาไทยและมีการป้องกัน CSV formula injection
- ฐานข้อมูล IndexedDB ในอุปกรณ์ และ export/import ไฟล์สำรอง JSON
- PWA manifest + service worker เพื่อเปิดหน้าหลักและใช้ข้อมูลในเครื่องต่อเมื่อออฟไลน์หลังจากเปิดครั้งแรกขณะออนไลน์
- การสำรองข้อมูลทั้งชุดไปยัง Supabase พร้อมบัญชีผู้ใช้และ Row Level Security (RLS)
- มีเมนูมิลค์เชคเป็นข้อมูลทดลอง โดยปิดการขายไว้จนกว่าจะเปิดเอง

## เทคโนโลยี

- HTML, CSS และ JavaScript แบบ ES modules ไม่มี build step และไม่มี dependency ภายนอกสำหรับหน้าขาย
- IndexedDB เป็นฐานข้อมูลหลักบนอุปกรณ์
- Service Worker cache สำหรับ app shell
- Supabase Auth REST API + PostgREST สำหรับสำรองชุดข้อมูล JSON ไปยังตาราง `pos_backups`

เหตุผลที่เลือก: โครงการเปิดอ่านและแก้ไขได้ง่าย ไม่ต้องติดตั้ง toolchain ก่อนทดลอง และข้อมูลการขายถูกเขียนลงในเครื่องก่อนทุกครั้ง ส่วนระบบสำรองออนไลน์ต้องตั้งค่า Supabase ของผู้ใช้เองก่อน ไม่ได้เปิดใช้งานจริงโดยอัตโนมัติทันทีที่ดาวน์โหลดโครงการ

## วิธีทดลองบนคอมพิวเตอร์

ต้องเปิดผ่านเว็บเซิร์ฟเวอร์ ไม่ควรดับเบิลคลิก `index.html` เพราะ Service Worker และความสามารถ PWA ต้องใช้ secure context (HTTPS หรือ localhost)

ใช้ Python หากติดตั้งอยู่แล้ว:

```bash
cd just-mellow-pos
python -m http.server 8000
```

จากนั้นเปิด `http://localhost:8000` ใน Chrome/Edge/Firefox ที่รองรับ IndexedDB และ ES modules

หากกำลังทดลองบนโทรศัพท์เครื่องจริง ให้ deploy โฟลเดอร์นี้ไปยัง static hosting ที่รองรับ HTTPS เช่น GitHub Pages, Netlify หรือบริการ static hosting อื่น การเปิด `localhost` บนโทรศัพท์จะหมายถึงตัวโทรศัพท์เอง ไม่ใช่คอมพิวเตอร์ เว้นแต่ตั้งค่าเครือข่ายให้ถูกต้อง

## วิธีติดตั้งบน Android

1. เปิด URL ที่ deploy ด้วย HTTPS ใน Chrome
2. ใช้เมนู `Install app` หากแสดง หรือเมนูเบราว์เซอร์ > `Add to Home screen`
3. เปิดจากไอคอน JUST MELLOW POS
4. เปิดหน้าแอปขณะออนไลน์อย่างน้อยครั้งแรก เพื่อให้ service worker cache ไฟล์แอปก่อนใช้งานออฟไลน์

## วิธีเพิ่มบนหน้าจอ iPhone/iPad

1. เปิด URL ผ่าน Safari ด้วย HTTPS
2. กด Share
3. เลือก Add to Home Screen
4. เปิดจากไอคอนที่สร้างขึ้น

รายละเอียดการแสดงปุ่มติดตั้งแตกต่างกันตามระบบปฏิบัติการและเบราว์เซอร์ PWA ไม่ใช่ไฟล์ APK และไม่ต้องส่งขึ้น Play Store

## ตั้งค่า Supabase สำหรับสำรองออนไลน์

> ต้องมีบัญชีและโปรเจกต์ Supabase ของตัวเอง แผนบริการและเงื่อนไขอาจเปลี่ยนแปลงได้ ตรวจสอบราคา/ข้อจำกัดในบัญชี Supabase ก่อนใช้จริง

1. สร้างโปรเจกต์ Supabase
2. เปิด SQL Editor แล้วรันไฟล์ `supabase-setup.sql`
3. ไปยังหน้า Project API settings แล้วคัดลอก Project URL และ **anon/public publishable key**
4. ใน JUST MELLOW POS เปิดแท็บ `ตั้งค่า`
5. กรอก Project URL และ public key แล้วกดบันทึก
6. สมัครหรือเข้าสู่ระบบด้วยอีเมลและรหัสผ่านของบัญชี Supabase Auth
7. หากระบบยืนยันอีเมล ให้กดยืนยันก่อนเข้าสู่ระบบ
8. ครั้งแรกที่พบข้อมูลสำรองออนไลน์ ระบบจะถามว่าจะใช้ข้อมูลจากออนไลน์หรือเขียนข้อมูลในเครื่องทับชุดสำรอง ต้องเลือกเองเพื่อป้องกันข้อมูลถูกเขียนทับโดยไม่ตั้งใจ
9. หลังเชื่อมต่อเรียบร้อย การเปลี่ยนแปลงข้อมูลจะถูกสำรองเมื่อออนไลน์ ระบบยังขายต่อได้ในเครื่องขณะออฟไลน์ และจะลองสำรองเมื่อกลับมาออนไลน์

**ความปลอดภัย:** ใช้เฉพาะ anon/public publishable key ร่วมกับ RLS ที่ตั้งค่าตาม SQL นี้ ห้ามใส่ `service_role` key หรือ secret key ในแอปฝั่งผู้ใช้ ระบบนี้สำรองข้อมูลร้านเป็น JSON หนึ่งชุด เหมาะกับร้านขนาดเล็กและการสำรองข้ามอุปกรณ์ ไม่ใช่ฐานข้อมูลออนไลน์แบบหลายเครื่องที่ซิงก์การแก้ไขพร้อมกันอย่างเต็มรูปแบบ

### ข้อจำกัดด้านการสำรอง

- การสำรองออนไลน์ต้องตั้งค่า Supabase และลงชื่อเข้าใช้ก่อน จึงจะทดสอบการส่ง/รับข้อมูลจริงได้
- ถ้าออนไลน์ไม่ได้หรือ Supabase มีปัญหา การขายในเครื่องยังทำงานได้ แต่ข้อมูลใหม่จะรอสำรอง
- การสำรองอัตโนมัติต้องให้แอปเปิดทำงานขณะออนไลน์ เบราว์เซอร์อาจพักการทำงานเบื้องหลังเมื่อปิดแอปหรือพักหน้าจอ หลังกลับมาเปิดแอปและออนไลน์ ระบบจะตรวจสอบและสำรองข้อมูลที่ค้างไว้
- หากข้อมูลออนไลน์และในเครื่องไม่ตรงกัน ระบบจะถามก่อนเลือกชุดข้อมูล ไม่เลือกทับให้อัตโนมัติ
- ไฟล์สำรอง JSON เป็นทางเลือกสำรองที่ไม่พึ่งอินเทอร์เน็ต ควรดาวน์โหลดเก็บไว้นอกโทรศัพท์เป็นระยะ
- อย่าล้างข้อมูลเบราว์เซอร์หรือถอนการติดตั้งก่อนมั่นใจว่ามีข้อมูลสำรองที่กู้คืนได้

## ชุดเมนูเริ่มต้น

- พุดดิ้งนมสดคาราเมล, กาแฟ, ชาไทย, ชาเขียว, โกโก้ (30 บาทเป็นราคาเริ่มต้น)
- ชาผลไม้รวม, องุ่น, แอปเปิล, ส้ม (50 บาทเป็นราคาเริ่มต้น)
- มิลค์เชคช็อกโกแลต, วานิลลา, สตรอว์เบอร์รี และกาแฟ (ตั้งราคาเป็นข้อมูลทดลองและปิดการขายไว้)

ราคาและต้นทุนทั้งหมดแก้ไขได้จากเมนูสินค้า ต้นทุนเริ่มต้นเว้นว่างไว้โดยตั้งใจ เพื่อไม่สร้างตัวเลขต้นทุนที่ไม่มีข้อมูลจริง

## การทดสอบ

ชุดทดสอบกฎคำนวณสามารถรันด้วย Node.js:

```bash
node --test tests/test-domain.mjs
```

ไฟล์ `tests/sample-backup.json` เป็นข้อมูลสมมติสำหรับทดลองรายงาน มีทั้งบิลสำเร็จและบิลยกเลิก หากนำเข้าไฟล์นี้ ข้อมูลสินค้าและบิลปัจจุบันในเครื่องจะถูกแทนที่ตามคำเตือนของแอป ควรใช้ก่อนเริ่มกรอกยอดขายจริงเท่านั้น

ทดสอบ UI ด้วยตนเองหรือผ่าน browser automation โดยเน้นสร้างบิลด้วยวิธีชำระเงินทั้ง 3 แบบ, ยกเลิกบิล, คำนวณรายงาน, export CSV, ปิดอินเทอร์เน็ตหลังเปิด app shell ครั้งแรก และเชื่อม Supabase จริงหลังตั้งค่า ตาราง/RLS/Auth

## โครงสร้างโครงการ

- `index.html` — markup และหน้าหลัก
- `styles.css` — responsive UI
- `app.js` — logic หน้าร้าน ประวัติ รายงาน และตั้งค่า
- `db.js` — IndexedDB และนำเข้า/ส่งออก snapshot
- `domain.js` — สูตรคำนวณ การตรวจสอบข้อมูล และ CSV
- `cloud.js` — Supabase Auth และ API สำหรับ backup
- `sw.js` — app-shell cache / offline fallback
- `manifest.webmanifest` — PWA metadata
- `supabase-setup.sql` — ตารางและ RLS policies
- `tests/test-domain.mjs` — domain/calculation unit tests
- `tests/test-cloud.mjs` — cloud API tests with mocked responses
- `tests/sample-backup.json` — synthetic test backup for safely evaluating the reporting workflow (importing it replaces current product and bill data)
- `PROGRESS.md` — ความคืบหน้าและรายการทดสอบ

## หมายเหตุสำหรับการใช้งานจริง

นี่คือรุ่นทดสอบ Round 1 ไม่ใช่ระบบบัญชีหรือระบบชำระเงินที่ผ่านการรับรอง ไม่มีการตรวจสอบเงินจริงจาก QR/การโอน และกำไรที่แสดงเป็นกำไรขั้นต้นจากต้นทุนสินค้าต่อหน่วยเท่านั้น ไม่รวมค่าใช้จ่ายทั่วไป ภาษี หรือค่าธรรมเนียมอื่น ๆ ก่อนใช้งานขายจริง ควรตรวจสอบขั้นตอนสำรอง/กู้คืนบนอุปกรณ์ที่ใช้งานและเก็บไฟล์สำรองไว้นอกเครื่องอย่างสม่ำเสมอ
